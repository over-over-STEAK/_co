# IC 設計與 EDA 學習筆記

> 從硬體描述到晶片佈局：理解電子設計自動化的流程與演算法。
>
> 本文為概念整理與手算示例，並未執行實際晶片製造流程或佈局效能實驗。

## 一、什麼是 EDA？

EDA 全名為 Electronic Design Automation，中文是「電子設計自動化」。它是一系列協助工程師描述、驗證、最佳化與實現電子電路的工具與方法。

IC（Integrated Circuit，積體電路）將許多電子元件整合在晶片上。面對大量電晶體與連線，工程師需要用 EDA 工具管理設計複雜度，檢查功能，並產生符合製程需求的實體設計資料。

可以把設計過程想成規劃一座城市：電路功能決定城市需要哪些建築，佈局決定建築位置，繞線安排道路；即使建築彼此靠近，也不代表道路一定不塞車。

## 二、從 RTL 到 GDSII 的設計流程

RTL 是 Register Transfer Level（暫存器傳輸層級），描述資料如何在暫存器間傳遞，以及其間的組合邏輯。GDSII 則是用來交換積體電路版圖幾何資料的格式之一。

| 階段 | 主要工作 | 需要回答的問題 |
| --- | --- | --- |
| 規格與架構 | 定義功能、介面、時脈及資源需求 | 電路要完成什麼任務？ |
| RTL 設計與驗證 | 撰寫硬體描述，透過模擬或形式方法檢查 | 功能是否符合規格？ |
| 邏輯合成 | 將 RTL 轉換並映射為目標元件庫的網表 | 要用哪些邏輯元件實現？ |
| 晶片規劃 | 安排核心區域、大型模組、I/O 與電源結構 | 晶片空間要如何分配？ |
| 佈局 | 決定標準元件的位置並進行合法化 | 元件如何安排才合理？ |
| 時脈樹合成 | 建立時脈分配網路 | 如何控制時脈延遲與偏移？ |
| 繞線 | 在金屬層上建立實際連線 | 訊號能否在規則限制內接通？ |
| 檢查與交付 | 時序、實體規則、連線一致性等檢查 | 是否符合交付製造的要求？ |

這不是只走一次的直線流程。若繞線後發現時序或擁塞問題，可能需要回到佈局甚至更早的階段調整。

## 三、EDA 與軟體編譯器的關聯

兩者都會把較高階的描述轉換成較低階的表示，並在過程中進行分析與最佳化。

| 比較項目 | 軟體編譯 | 數位 IC 設計 |
| --- | --- | --- |
| 輸入描述 | C、C++ 等程式 | Verilog、SystemVerilog 等 RTL |
| 中間表示 | 語法樹、控制流程圖等 | 運算結構、邏輯網表等 |
| 最佳化目標 | 執行效率、程式大小等 | 功耗、效能、面積等 |
| 後續結果 | 機器碼或其他目標碼 | 映射後網表，再經實體設計形成版圖 |

這個比喻有其限制：硬體必須處理實際面積、導線延遲、供電與製造規則，不能只檢查邏輯計算結果。

## 四、如何把電路轉成數學問題？

### 4.1 網表與超圖

網表記錄元件與接腳的連接關係。可以將元件視為節點，將同一條訊號網路（net）所連接的多個接腳視為一條超邊。

一般圖的一條邊連接兩個節點；超圖的一條超邊能連接多個節點，因此適合描述一個輸出同時連接多個輸入的情況。

### 4.2 佈局的三項常見考量

| 考量 | 意義 | 只追求這一項可能造成的問題 |
| --- | --- | --- |
| 線長 | 讓有連接關係的元件距離較短 | 元件過度集中 |
| 密度與重疊 | 避免超出區域容量或互相重疊 | 元件過度分散、線長增加 |
| 繞線擁塞 | 避免局部連線需求超過資源 | 為避開擁塞而繞遠路 |

教學上可以寫成簡化的代價函數：

```text
Cost = α × 線長估計 + β × 密度／重疊懲罰 + γ × 擁塞懲罰
```

α、β、γ 表示各項的重要程度。各項尺度不同，實作時需要適當正規化或調整權重。這是概念模型，不代表所有工具都使用同一條公式；實際工具也會考慮時序、固定元件與其他限制。

### 4.3 HPWL：半周長線長估計

對一條 net，找出所有接腳座標的最小包圍矩形：

```text
HPWL(net) = (最大 x − 最小 x) + (最大 y − 最小 y)
總 HPWL = 所有 net 的 HPWL 總和
```

假設一條 net 的三個接腳位於 A(1, 1)、B(5, 2)、C(3, 6)：

```text
HPWL = (5 − 1) + (6 − 1) = 9
```

若只將 C 移至 (3, 4)，其他接腳不變：

```text
HPWL = (5 − 1) + (4 − 1) = 7
```

這表示線長估計下降，但仍須檢查是否造成重疊或擁塞。HPWL 不是繞線完成後的實際導線長度，也不包含所有障礙物與金屬層限制。

補充：固定 net 成員、把座標視為連續變數時，HPWL 是凸但不處處可微的函數；整體佈局問題仍受不重疊、離散位置與其他複雜限制影響。

## 五、三種佈局最佳化思路

### 5.1 貪婪式局部改善

每次嘗試移動或交換元件，若代價降低就接受。

- 優點：規則簡單，容易觀察改善過程。
- 限制：可能停在局部最佳解，無法跨過需要暫時變差的區域。
- 注意：只縮短線長而沒有密度限制，可能把元件擠在一起。

### 5.2 模擬退火

模擬退火允許以一定機率接受較差的候選解，藉此探索其他區域。令代價差為 ΔC = 新代價 − 舊代價：

```text
ΔC ≤ 0：接受新解
ΔC > 0：以 exp(−ΔC / T) 的機率接受新解
```

其中 T 是正的溫度參數。高溫時較容易接受變差的移動，降溫後逐漸偏向保留較好的解。

例如 ΔC = 2、T = 4 時，接受機率約為 0.607；若 T = 0.5，接受機率約為 0.018。

- 優點：有機會跳離局部最佳解。
- 限制：結果受到初始解、亂數、移動方式與降溫排程影響。
- 不保證有限次執行就能找到全域最佳解。

### 5.3 解析式佈局

將元件座標當成連續變數，建立可供數值最佳化處理的線長與密度模型，透過梯度相關方法更新位置。

常見概念是：連線產生讓相關元件靠近的作用，而密度懲罰促使過度集中的元件分散。部分方法使用類似靜電場的密度模型，但不能把所有解析式佈局都視為同一種電場演算法。

連續最佳化之後，還需要合法化，將元件移到允許的位置並消除重疊。OpenROAD 的全域佈局與詳細佈局文件可作為實際工具的閱讀入口。[2][3]

| 方法 | 如何選擇移動 | 主要限制 |
| --- | --- | --- |
| 貪婪式局部改善 | 只接受較好的候選解 | 容易停在局部最佳 |
| 模擬退火 | 允許機率性接受較差解 | 需要選擇溫度與迭代設定 |
| 解析式佈局 | 依連續目標函數進行數值更新 | 模型設計與後續合法化很重要 |

## 六、為什麼線短不代表一定繞得出來？

假設許多元件都集中在晶片中央，雖然它們彼此很近，但大量訊號也必須通過相同區域。若可用的金屬走線資源不足，就可能出現擁塞。

因此，評估佈局不能只看 HPWL。還需要觀察區域密度、擁塞與後續繞線結果。RUDY 是用於預估繞線需求的模型之一；預估結果仍不能代替實際詳細繞線驗證。

## 七、與 Nand2Tetris 作業的關聯

Nand2Tetris 從邏輯閘逐步組合出加法器、ALU、暫存器、CPU 與電腦。它能幫助理解「用小元件組成大系統」與「透過測試驗證功能」的觀念。

| Nand2Tetris 作業 | 對應的學習概念 |
| --- | --- |
| And、Mux 等 HDL 元件 | 描述硬體結構與連線 |
| ALU、CPU.hdl | 將運算、控制與儲存單元組合 |
| .tst 與 .cmp | 提供測試步驟並比對預期結果 |
| Computer.hdl | 整合 CPU、記憶體與指令來源 |

Nand2Tetris 的 HDL 是課程專用語言，不能直接當成標準 Verilog 丟進一般 ASIC 合成流程。功能模擬成功，也不表示已完成實體佈局、時序驗證或晶片製造。

## 八、可以如何設計一個公平的比較實驗？

若進一步製作互動模擬器，可以採用以下方式：

1. 固定同一份網表、元件尺寸、晶片範圍與初始座標。
2. 記錄亂數種子，確保可以重現。
3. 讓不同方法使用相同的代價定義與權重。
4. 同時記錄迭代次數與執行時間，避免把不同計算量的「一步」當成相同成本。
5. 比較 HPWL、重疊、擁塞估計與合法化後的結果。
6. 使用多個種子重複實驗，觀察平均結果與變動程度。

## 九、重點整理與心得撰寫方向

EDA 將硬體設計中的許多工作轉化為可分析與求解的問題，包括邏輯轉換、圖與超圖模型、搜尋、數值最佳化及幾何檢查。它的價值不只是自動畫圖，而是協助工程師在多種限制下完成可實現的設計。

撰寫自己的心得時，可以回答：

- 從 Nand2Tetris 的功能驗證到真實晶片設計，還缺少哪些步驟？
- 為什麼線長、密度與擁塞需要一起考量？
- 模擬退火接受較差解的機制，有什麼用途？
- 如果只看到動畫中的元件變整齊，是否足以判定演算法比較好？
